You paste in the link your provider gave you, the app thinks about it, and then
a short error appears. What the message says rarely helps. The question that
matters is: is the fault yours, your network's, or your provider's?

There are five faults. They all look alike from the outside, and each one has a
tell. Finding the right one first is far quicker than tearing the setup down and
starting again.

## 1. The credentials are refused

**The tell:** it fails immediately. No waiting.

The server was reached and the server said no. Your network is fine; the account
is the problem. In order of how often it happens:

- **The password was mistyped.** Type it rather than pasting it. A trailing
  space picked up while copying is invisible to you and a different password to
  the server.
- **The subscription expired.** Xtream accounts end on a date, and after it not
  a single channel opens.
- **You are over the device limit.** Most providers cap how many devices may
  stream at once. A forgotten stream left running on the television is a
  surprisingly common cause of an "invalid user" error on the phone. Sign out on
  the other device and try again.

Read the server address once more, too:
[which connection format you were given](/blog/xtream-codes-vs-m3u/) changes
what a correct address looks like.

## 2. The server is never reached

**The tell:** a long wait, then a timeout. The error arrives late.

This time nobody said no — nobody answered at all.

- **The port is missing.** Most Xtream panels do not run on port 80. The address
  is `http://example.com:8080`, not `http://example.com`, and if your provider
  gave you a port you have to include it.
- **Your network blocks the provider.** If it fails on Wi-Fi, try the same list
  on mobile data. A different outcome puts the fault in the connection rather
  than the list. For a permanent fix, set a proxy under **Settings → Proxy**.
- **The address is gone.** Providers change domains and retire the old ones.
  Nothing on your side fixes that; ask for the current address.

## 3. It loads, and arrives empty

**The tell:** no error, the progress bar completes, and then there are no
channels.

The app received something — but what it received was not a playlist. Two
versions of this:

- **The server returned an error page instead of a list.** It looks like the
  link worked, because technically a reply came back; the text inside it is a
  notice page. Opening the link in a browser and checking whether the first line
  reads `#EXTM3U` settles it in seconds.
- **The subscription lapsed and the panel serves an empty list.** Some panels
  answer expired accounts with a valid playlist containing zero channels rather
  than an error. It looks identical to the case above.

## 4. The secure connection fails

**The tell:** it only happens on `https` addresses. Anything on `http` works.

This is the one nobody suspects and the easiest to fix: **the device clock is
wrong.** Setting up an encrypted connection involves checking that the server's
certificate is currently valid, and that check trusts the clock on your device.
If the date has drifted by days, every certificate looks invalid and the
connection is refused with no useful explanation.

Set date and time to automatic and try the list again.

## 5. The list opens, the channels do not

**The tell:** names, categories and logos are all there. Nothing plays.

This is no longer a playlist problem. A playlist is text containing names and
addresses, and
[the player's job](/blog/what-an-iptv-player-does/) is to connect to the
address. If you can read the names, the list arrived correctly — what is failing
is the far end of the addresses.

Try two or three different channels. If **everything** fails, the block is at
the account or the network. If **one** channel fails, that stream is dead at the
provider and nothing in the app can revive it. If it plays but keeps breaking
up, that is a different problem entirely and it lives
[in the path between you and the server](/blog/fix-iptv-buffering/).

## Telling them apart quickly

Three questions, three minutes:

1. **Did the error come instantly or after a wait?** Instantly points at fault
   one; after a wait points at fault two.
2. **Does mobile data behave differently?** If yes, the fault is the network.
3. **What happens when you pull to refresh on the home screen?** That re-reads
   the source instead of the cached catalogue, so anything fixed at the
   provider's end shows up there first.

If you are still stuck after that, write to your provider before
[rebuilding the setup](/blog/set-up-your-first-playlist/). Four of the five
faults above cannot be fixed from your side, and asking the right question beats
repeating the whole installation.
