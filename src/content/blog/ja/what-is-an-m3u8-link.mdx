**m3u8リンクとは、M3U形式で書かれ、UTF-8で保存された小さなテキストファイルの
アドレスです。**映像そのものは入っていません。何を手にしているのかは中身で
決まり、実際には、まったく性格の違う次の二つのどちらかです。

- **HLSの配信。** チャンネル一つ、または動画一本を、プレイヤーが順番に取得する
  短いセグメントの一覧として記述したものです。ウェブの世界でこの拡張子が
  指すのは、たいていこちらです。
- **チャンネルのプレイリスト。** 数百のチャンネル名とそのストリームの
  アドレスを並べたもので、`.m3u`ファイルとまったく同じ中身を、UTF-8の文字で
  保存しただけです。こちらについては
  [M3UとM3U8の違い](/ja/blog/m3u-と-m3u8-の違い/)で解説しています。

アドレスバーに入っているときは見分けがつかないのに、動きはまるで違います。
ですから、最初の仕事は二つを見分けることです。

## どちらなのかを見分ける

リンクをブラウザで開くか、ファイルとして保存してテキストエディタで開きます。
最初の数行を見れば分かります。

**プレイリスト**は住所録のように読めます。名前、アドレス、名前、アドレスの
繰り返しです。

```
#EXTM3U
#EXTINF:-1 tvg-id="one.example" group-title="ニュース",チャンネル一
http://example.com/live/one.m3u8
#EXTINF:-1 tvg-id="two.example" group-title="映画",チャンネル二
http://example.com/live/two.m3u8
```

**HLSの配信**は時刻表のように読めます。用意されている画質を並べているか、

```
#EXTM3U
#EXT-X-STREAM-INF:BANDWIDTH=2500000,RESOLUTION=1280x720
720p/index.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=6000000,RESOLUTION=1920x1080
1080p/index.m3u8
```

あるいはセグメントそのものを並べています。

```
#EXTM3U
#EXT-X-TARGETDURATION:6
#EXT-X-MEDIA-SEQUENCE:48213
#EXTINF:6.0,
segment48213.ts
#EXTINF:6.0,
segment48214.ts
```

チャンネル名や`group-title`があればプレイリスト、`#EXT-X-`で始まる行があれば
配信です。

## HLSは実際にどう再生されるのか

HLS（HTTP Live Streaming）は、インターネットで映像を届ける方式として
いちばん広く使われているもので、`.m3u8`ファイルはその目次にあたります。

最初のファイルである**マスタープレイリスト**には、同じ番組が複数の画質で、
それぞれに必要な帯域とともに並んでいます。プレイヤーはその一つを選び、
対応する**メディアプレイリスト**を開きます。そこには、数秒ずつの次の
セグメントがいくつか書かれています。プレイヤーはそれを取得して再生し、
メディアプレイリストを読み直して次のセグメントを見つけます。生放送の
チャンネルならこの一覧は前へ進み続け、映画なら終わりを示すタグで閉じられて
いて、プレイヤーは全体の長さを把握できます。

うまくできているのは、セグメントの切れ目ごとに画質を切り替えられる点です。
回線が落ち込むと、止まる代わりに軽い版へ下がり、余裕が戻ればまた上がります。
Vidonzoは生放送のチャンネルをいちばん軽い版から始めて映像をすばやく出し、
そこから自動で画質を上げていきます。HLSとほかの方式との比較は
[配信方式の解説記事](/ja/blog/hls-dash-rtsp-の-違い/)にまとめています。

## m3u8リンクの再生方法

**プレイリストだった場合**は、IPTVプレイヤーに渡すものです。プレイヤーが
チャンネル、カテゴリ、番組表に組み立ててくれます。Vidonzoなら
**サービスを追加 → M3U リンク**を選び、**M3U/M3U8 プレイリスト URL**に
貼り付けます。プレイリストがファイルで届いたなら、**M3U ファイル**から
端末内のファイルを読み込めます。

**配信一本だった場合**は、分かりやすい方法が三つあります。

1. **VLC。** *メディア → ネットワークストリームを開く*（Macでは*ファイル →
   ネットワークを開く*）を選び、リンクを貼り付けて再生します。VLCはまさに
   これが得意です。[どこからVLCでは足りなくなるか](/ja/blog/vlc-を-iptv-プレイヤー-に-できるか/)は
   また別の問題です。
2. **Safari。** Appleのブラウザは標準でHLSを再生できるので、`.m3u8`の直リンクを
   開くとそのまま動画になることがよくあります。ほかのブラウザでは対応が
   まちまちで、HLSプレイヤーを組み込んだウェブページの中でしか再生できない
   ものも多くあります。
3. **プレイリストで包む。** IPTVプレイヤーが期待しているのは一覧で、一件だけの
   一覧も一覧です。次の三行を、自分の付けたい名前とアドレスに書き換えて、
   `stream.m3u`という名前のテキストファイルに保存します。

   ```
   #EXTM3U
   #EXTINF:-1,自分の配信
   https://example.com/live/index.m3u8
   ```

   Vidonzoはこれをほかのプレイリストと同じく**M3U ファイル**から読み込み、
   その配信は名前付きで、ほかのものと並んでライブラリに収まります。

## m3u8リンクが再生できなくなる理由

昨日は再生できたリンクが今日はだめ、というとき、原因はたいてい次のどれかです。

- **有効期限が組み込まれていた。** 多くの配信アドレスには、`?`より後ろの部分に
  トークンや署名が入っています。`token=`、`expires=`、`sig=`といったものです。
  有効なのは一回の視聴か数時間だけで、それを過ぎるとサーバーは403で拒否します。
  プレイヤーには何の問題もなく、鍵の期限が切れただけです。
- **発行元でしか使えない。** サーバーによっては、どのアプリやページから要求が
  来たかを確かめ、それ以外をすべて断ります。
- **セグメントが先へ進んでしまった。** 生放送のメディアプレイリストに書かれて
  いるのは、直近のいくつかのセグメントだけです。ファイルとして保存した写しは、
  数秒で古くなります。
- **配信が終わった、または移った。** 404は、そのアドレスがもう存在しないという
  意味です。

`.m3u8`のチャンネルが並ぶプレイリスト全体は読み込めるのに何も再生されない
なら、拡張子が原因であることはまずありません。問題は中に書かれたアドレスの
ほうです。そして、再生が始まって数秒で止まるなら、
[それはバッファリングではなく切断で](/ja/blog/数秒-で-映像-が-止まる/)、
原因も別にあります。

## まとめ

`.m3u8`は目次であって、映像そのものではありません。中にチャンネル名があれば
プレイリストなので、プレイヤーに渡します。`#EXT-X-`の行があればHLSの配信一本
なので、VLCかSafariで開くか、一行だけのプレイリストで包みます。そして、一度は
動いたのに今は動かないなら、ほかを疑う前に、アドレスに入った有効期限を
確かめてください。
