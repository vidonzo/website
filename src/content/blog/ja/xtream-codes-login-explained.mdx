**Xtream Codesのログインは、三つの情報でできています。サーバーURL（たいてい
`http://example.com:8080`のようにポート番号付き）、ユーザー名、パスワードです。**
この三つがそろうと、プレイヤーは決まった一覧を読むのではなく、事業者の
サーバーに生放送のチャンネル、映画、ドラマ、番組表を直接問い合わせられるように
なります。この種のログインで起きる問題は、ほとんどが三つのどれかを少しだけ
写し間違えたことから来ていて、間違いごとに見分けのつく症状があります。

## 三つの項目はどこから来るか

事業者から送られてきます。たいていは次のようなメッセージです。

```
URL:      http://example.com:8080
Username: tanaka42
Password: k7Qp9xWz
```

ログイン情報が別になっておらず、長いリンクが一本だけ届くこともあります。
そのリンクには三つとも入っています。

```
http://example.com:8080/get.php?username=tanaka42&password=k7Qp9xWz&type=m3u_plus&output=ts
```

左から読んでいきます。`/get.php`より前がすべて**サーバーURL**、`username=`の
あとの値が**ユーザー名**、`password=`のあとの値が**パスワード**です。残りは、
どのプレイリスト形式で送るかをサーバーに伝えているだけです。

逆方向にも使えます。三つの項目があれば、このリンクを自分で組み立てられます。
サーバーURL、`/get.php?username=`、ユーザー名、`&password=`、パスワード、
`&type=m3u_plus`の順につなぐだけです。M3Uリンクしか受け付けないプレイヤーで
役に立ちます。

## サーバーURLを分解する

`http://example.com:8080`は三つの部分でできていて、どれも大事です。

- **スキーム：`http://`か`https://`か。** 互いに置き換えはききません。事業者が
  書いたとおりに使ってください。Xtreamのサーバーの多くは素の`http`でしか
  応答せず、`https`で要求すると証明書のエラーになるか、何も返ってきません。
- **ホスト：`example.com`。** `203.0.113.10`のような数字だけのアドレスの
  こともあります。一文字違えば、サーバーはそもそも見つかりません。
- **ポート：`:8080`。** コロンのあとの数字は、同じサーバーの別の扉です。
  `http://example.com`と`http://example.com:8080`は別のアドレスで、
  「合っているように見える」ログインがどこにもつながらない理由として
  いちばん多いのが、このポートの付け忘れです。

入力欄に**入れない**ものは、ポートより後ろのすべてです。`/get.php`、
`/player_api.php`、`/c/`といったパスは、プレイヤーが自分で付け足します。

よくあるケースはVidonzoが整えます。スキームを省けば`http://`を補い、末尾の
スラッシュを取り除き、入力したポートはそのまま残します。

## ユーザー名とパスワード

どちらも大文字と小文字を区別します。そしてたいていは機械が作った文字列で、
`O`と`0`、`l`と`I`がよく似ています。ですから、

- **打たずに貼り付ける。** 事業者のメッセージからコピーします。
- **末尾の空白に注意。** メッセージからコピーすると、単語のあとの空白まで
  一緒に取ってしまうことがよくあります。サーバーはそれをパスワードの一部と
  みなします。
- **入れ違えない。** 当たり前に聞こえますが、でたらめな文字列が二つ並ぶと
  起こります。

ログイン情報は銀行のパスワードと同じくらい大切です。持っている人なら誰でも
あなたの契約を使えて、同時接続数の上限に達すると、あなた自身が締め出される
こともよくあります。Vidonzoはこれを端末の中にだけ保存し、
[どこかへ送る前に暗号化することもできます](/ja/blog/認証情報-を-暗号化-すべき-理由/)。

## プレイヤーはそれで何をするか

接続すると、プレイヤーはユーザー名とパスワードを添えてサーバーの
`player_api.php`を呼び出します。最初の応答はアカウントそのものについてで、
ログインが受け付けられたかどうかや、同時にいくつ接続できるかといった情報です。
そのあとにカテゴリ、チャンネル一覧、映画とドラマのカタログ、番組表が続き、
それぞれ必要になった時点で取得されます。

ここが素のM3Uリンクとの違いです。M3Uは決まったファイル一つで、問い合わせる
ことが何もありません。
[両方持っているとき、どちらを使うか](/ja/blog/xtream-codes-と-m3u-の違い/)は、主に
映画・ドラマと番組表が欲しいかどうかで決まります。

## Vidonzoに入力する

1. **サービスを追加**を選び、**Xtream Codes**を開きます。
2. **サーバー URL**にアドレスを貼り付けます。スキーム、ホスト、ポートまでで、
   その後ろは入れません。
3. **ユーザー名**と**パスワード**を貼り付けます。
4. 必要なら**サービス名（任意）**を付けて、**接続して保存**を押します。

保存する前にログインが確認されるので、間違いはあとで空のライブラリとして
現れるのではなく、その場で分かります。長い`get.php`のリンクしか持っていない
場合は、代わりに**M3U リンク**のタブに貼り付けてください。Vidonzoがそこから
三つの項目を読み取り、ログインが通れば、映画、ドラマ、番組表のそろった
Xtreamのサービスとして設定します。

## エラーメッセージの意味

- **「ユーザー名またはパスワードが正しくありません。」** サーバーには届いた
  うえで、ログインを拒否されています。大文字と小文字、似た文字、末尾の空白を
  確かめてください。期限切れや停止中のアカウントにも同じ答えを返すサーバーが
  あるので、パスワードに確信があるなら、アカウントの状態を事業者に問い合わせて
  ください。
- **「サーバーに接続できませんでした。」** そのアドレスでは何も応答していません。
  よくある原因は、ポートの抜けや間違い、`http`のところを`https`にしている、
  ホストの打ち間違いです。まれに、いま使っているネットワークが珍しいポートを
  遮断していることもあります。同じログインをモバイル通信で試せば、すぐに
  切り分けられます。
- **「サーバーの応答に時間がかかりすぎています。」** 届いてはいるものの、
  応答が遅い状態です。カタログがとても大きいと、最初の接続に時間がかかる
  ことがあります。何かを変える前に、もう一度試してください。
- **「サーバーのセキュリティ証明書を検証できませんでした。」** 証明書が無効な
  サーバーに`https`で接続しています。事業者が指定したスキームを使ってください。

ログインは通るのに、そのあとチャンネルが始まっては止まるなら、もうログインの
問題ではありません。[それは配信側の問題で](/ja/blog/数秒-で-映像-が-止まる/)、
接続数の上限はそのよくある原因の一つです。ソースが読み込めない失敗全般に
ついては、
[不親切なエラー一つの裏にある五つの失敗](/ja/blog/プレイリスト-が-読み込めない-とき/)を
ご覧ください。
