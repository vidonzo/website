**ไฟล์ M3U คือเพลย์ลิสต์ที่เป็นข้อความธรรมดา** แต่ละรายการคือที่อยู่ของเพลง
วิดีโอ หรือสตรีมทีวีสด ซึ่งส่วนใหญ่มีบรรทัดที่บอกชื่อและรายละเอียดนำหน้าอยู่
นามสกุลนี้มาจาก *MP3 URL* ซึ่งเป็นงานดั้งเดิมของมัน
ทุกวันนี้มันคือวิธีมาตรฐานที่ผู้ให้บริการ IPTV ใช้ส่งรายการช่อง
และ `.m3u8` ก็คือรูปแบบเดียวกันที่บันทึกเป็น UTF-8

รูปแบบนี้ขึ้นชื่อว่าเป็นของเชิงเทคนิค ซึ่งมันไม่สมควรได้รับ มันเป็นหนึ่งใน
รูปแบบที่เรียบง่ายที่สุดที่ยังใช้กันทุกวัน คือรายชื่อหนึ่งชุด รายการที่อยู่หนึ่ง
ชุด และหมายเหตุอีกไม่กี่อย่างที่จะมีหรือไม่มีก็ได้ คุณอ่านมันได้ในโปรแกรมแก้ไข
ข้อความ และพออ่านแล้ว พฤติกรรมหลายอย่างของเครื่องเล่นก็เลิกดูเหมือนเรื่องสุ่มสี่
สุ่มห้า (ถ้าแค่อยากเปิดเล่น
[วิธีเปิดไฟล์ M3U](/th/blog/วิธีเปิดไฟล์-m3u/) เป็นอีกเรื่องที่สั้นกว่า)

นี่คือเพลย์ลิสต์ที่สมบูรณ์และใช้งานได้จริง สองช่อง ไม่ตัดอะไรออก

```
#EXTM3U url-tvg="http://example.com/guide.xml"
#EXTINF:-1 tvg-id="one.example" tvg-name="Channel One" tvg-logo="http://example.com/one.png" group-title="ข่าว",ช่องหนึ่ง
http://example.com/live/one.ts
#EXTINF:-1 tvg-id="two.example" tvg-name="Channel Two" group-title="กีฬา",ช่องสอง
http://example.com/live/two.ts
```

รูปแบบทั้งหมดมีเท่านี้ ที่เหลือคือการเดินชมห้าบรรทัดนั้น

## บรรทัดหัวไฟล์

```
#EXTM3U
```

บรรทัดแรกต้องเป็นแบบนี้เป๊ะ ๆ และหน้าที่เดียวของมันคือบอกว่า "ที่ตามมาคือ M3U
แบบขยาย" ไฟล์ที่ขาดบรรทัดนี้อาจยังโหลดได้อยู่ แต่เครื่องเล่นก็ไม่มีเหตุผลจะ
คาดหวังบรรทัดคำอธิบายที่ตามมา

หัวไฟล์ยังเป็นที่ที่เพลย์ลิสต์ชี้ไปยังผังรายการของตัวเองได้ด้วย

```
#EXTM3U url-tvg="http://example.com/guide.xml"
```

`url-tvg` (หรือ `x-tvg-url` ซึ่งหมายถึงสิ่งเดียวกัน) ระบุชื่อไฟล์ XMLTV —
[เอกสารแยกต่างหากที่มีตารางเวลาของตัวเอง](/th/blog/epg-ผังรายการ-ทำงานอย่างไร/) — ซึ่งบอกว่าตอนนี้
ฉายอะไรและต่อไปคืออะไร เมื่อเพลย์ลิสต์มีบรรทัดนี้แล้วผังยังไม่ขึ้น อย่างน้อย
คุณก็รู้ว่าควรโทษไฟล์ไหนในสองไฟล์

## บรรทัดคำอธิบาย

```
#EXTINF:-1 tvg-id="one.example" tvg-name="Channel One" group-title="ข่าว",ช่องหนึ่ง
```

`#EXTINF` เป็นการเปิดหนึ่งรายการ อ่านมันเป็นสามส่วน

**ตัวเลข** ถัดจากทวิภาคทันทีคือความยาวเป็นวินาที สำหรับโทรทัศน์สดจะเป็น `-1`
หมายถึง "ไม่มีความยาวตายตัว" — การถ่ายทอดก็แค่ดำเนินต่อไป ส่วนภาพยนตร์อาจเห็น
ตัวเลขจริงแทน

**แอตทริบิวต์** คู่ `key="value"` ที่จะมีหรือไม่มีก็ได้ ตัวที่สำคัญ

- **`tvg-id`** — ตัวระบุที่เชื่อมช่องนี้เข้ากับรายการในผัง XMLTV นี่คือสาเหตุที่
  พบบ่อยที่สุดของอาการผังโหลดได้แต่ไม่แสดงอะไรเลย เพราะเพลย์ลิสต์กับผังใช้ตัวระบุ
  ไม่ตรงกัน จึงจับคู่กันไม่ได้สักอย่าง
- **`tvg-name`** — ชื่อช่องสำหรับใช้จับคู่กับผัง ซึ่งไม่ได้เป็นชื่อเดียวกับที่
  แสดงบนหน้าจอเสมอไป
- **`tvg-logo`** — ที่อยู่ของโลโก้ช่อง สิ่งเหล่านี้คือรูปภาพที่ดึงผ่านเครือข่าย
  ช่องละหนึ่งรูป และนั่นคือเหตุผลที่รายการยาว ๆ ต้องใช้เวลาสักครู่กว่าจะดูครบใน
  ครั้งแรก
- **`group-title`** — หมวดที่ช่องนั้นถูกจัดเก็บไว้ ทุกหัวข้อหมวดที่คุณเลื่อนผ่าน
  ในเครื่องเล่นถูกพิมพ์ไว้ตรงนี้ โดยผู้ให้บริการของคุณ ทีละช่อง และนี่ก็เป็นเหตุผล
  ที่[การจัดหมวดด้วยตัวเองนั้นคุ้มค่า](/th/blog/จัดระเบียบ-เพลย์ลิสต์-iptv-ช่องเยอะ/)

**ชื่อที่แสดง** หลังเครื่องหมายจุลภาค ทุกอย่างจนจบบรรทัดคือชื่อที่คุณเห็นจริง ๆ
มันเป็นข้อความล้วนไม่มีเครื่องหมายคำพูด ดังนั้นจุลภาคที่อยู่ในชื่อช่องจึงเป็น
อันตรายจริงของรูปแบบนี้

## ที่อยู่

```
http://example.com/live/one.ts
```

บรรทัดถัดจาก `#EXTINF` ทันทีคือที่ที่วิดีโออาศัยอยู่ มันเป็นบรรทัดเดียวในไฟล์
ที่แตะเครือข่ายตอนเล่น และเป็นตัวกำหนดว่า
[สตรีมจะทำงานอย่างไร](/th/blog/hls-dash-rtsp-โปรโตคอลสตรีมมิง/): ที่อยู่ลงท้าย `.m3u8`
คือสตรีม HLS ที่ส่งมาเป็นชิ้น ๆ ส่วนที่อยู่ลงท้าย `.ts` คือกระแสส่งข้อมูลต่อเนื่อง

จากตรงนี้ได้ข้อสรุปที่ใช้ได้จริงสองข้อ ข้อแรก รายการที่มีบรรทัดคำอธิบายแต่ไม่มี
ที่อยู่จะมองไม่เห็น เพราะไม่มีอะไรให้เล่น ข้อสอง เพลย์ลิสต์ที่โหลดสมบูรณ์แบบแต่
ทุกช่องเล่นไม่ได้ คือเพลย์ลิสต์ที่ชื่อยังดีอยู่แต่ที่อยู่ตายไปแล้ว ซึ่งเป็นปัญหา
[ที่ผู้ให้บริการ ไม่ใช่ที่เครื่องเล่น](/th/blog/เครื่องเล่น-iptv-ทำอะไร/)

## สิ่งที่ไม่ได้อยู่ในนั้น

สิ่งที่รูปแบบนี้บรรจุไม่ได้ก็ให้ความรู้ไม่แพ้กัน

- **ไม่มีวิดีโอ** เพลย์ลิสต์สี่หมื่นช่องคือข้อความไม่กี่เมกะไบต์ ไม่มีสักเฟรม
  เดียวที่เป็นภาพ
- **ไม่มีการเข้าสู่ระบบ** ที่ใดต้องใช้ข้อมูลรับรอง มักฝังอยู่ในตัวที่อยู่เอง
  นั่นคือเหตุผลที่ควรปฏิบัติต่อลิงก์เพลย์ลิสต์เหมือนรหัสผ่าน
- **ไม่มีการเชื่อมต่อที่มีชีวิต** ไฟล์คือภาพนิ่งของสิ่งที่มีอยู่ ณ ตอนที่คุณดึง
  มา ช่องที่เพิ่มเข้ามาภายหลังจะไม่อยู่ในนั้น นั่นคือความต่างที่แท้จริงจาก
  [API ของ Xtream Codes](/th/blog/xtream-codes-หรือ-m3u/) และเป็นเหตุผลว่าทำไม
  [รายการอยู่ที่ไหนจึงสำคัญ](/th/blog/ลิงก์-เพลย์ลิสต์-หรือ-ไฟล์-ในเครื่อง/)
- **ไม่มีการประกาศชุดอักษร** ไม่มีอะไรในรูปแบบนี้ที่ระบุการเข้ารหัสของตัวเอง และ
  ด้วยเหตุนี้เองบางครั้ง
  [ชื่อช่องจึงมาถึงในรูปสัญลักษณ์](/th/blog/ชื่อช่อง-เป็น-ตัวอักษร-ประหลาด/)

## อ่านของคุณเอง

ถ้ารายการทำตัวแปลก ๆ ให้เปิดขึ้นมาดู `#EXTM3U` ที่หายไป, `group-title` ที่ว่าง
ทุกบรรทัด, `tvg-id` ที่ไม่มีเลยทั้งไฟล์, ชื่อที่มีจุลภาคหลงเข้าไป — แต่ละอย่างมี
ลายเซ็นเฉพาะตัวในเครื่องเล่น และแต่ละอย่างมองเห็นได้ในการอ่านราวสิบวินาที

รูปแบบนี้เล็กพอที่จะจำได้ทั้งหมดในหัว นั่นเป็นเรื่องไม่ธรรมดา และควรใช้ประโยชน์
จากมัน
