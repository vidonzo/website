За файлом M3U закрепилась репутация чего-то технического, которой он не
заслуживает. Это один из простейших форматов, до сих пор используемых
ежедневно: список названий, список адресов и несколько необязательных пометок.
Его можно прочитать в текстовом редакторе, и как только вы это сделаете, многое
в поведении плеера перестанет казаться произвольным.

Вот полноценный рабочий плейлист. Два канала, ничего не опущено.

```
#EXTM3U url-tvg="http://example.com/guide.xml"
#EXTINF:-1 tvg-id="one.example" tvg-name="Channel One" tvg-logo="http://example.com/one.png" group-title="Новости",Канал Один
http://example.com/live/one.ts
#EXTINF:-1 tvg-id="two.example" tvg-name="Channel Two" group-title="Спорт",Канал Два
http://example.com/live/two.ts
```

Это весь формат целиком. Дальше — экскурсия по этим пяти строкам.

## Заголовок

```
#EXTM3U
```

Первая строка должна выглядеть ровно так, и её единственная задача — сообщить:
«дальше идёт расширенный M3U». Файл без неё, возможно, всё равно загрузится, но
у плеера не будет причин ожидать строк описания, которые идут следом.

Заголовок — ещё и место, где плейлист может указать на собственную
телепрограмму:

```
#EXTM3U url-tvg="http://example.com/guide.xml"
```

`url-tvg` (или `x-tvg-url`, что означает то же самое) называет файл XMLTV —
[отдельный документ со своим расписанием](/ru/blog/как-работает-телепрограмма-epg/), который сообщает,
что идёт сейчас и что будет дальше. Если плейлист это несёт, а программа всё
равно не появляется, вы хотя бы знаете, какой из двух файлов виноват.

## Строка описания

```
#EXTINF:-1 tvg-id="one.example" tvg-name="Channel One" group-title="Новости",Канал Один
```

`#EXTINF` открывает одну запись. Читайте её в три приёма.

**Число.** Сразу за двоеточием идёт длительность в секундах. Для прямого эфира
это `-1`, то есть «без фиксированной длины» — поток просто продолжается. Для
фильма вместо этого можно увидеть настоящее число.

**Атрибуты.** Необязательные пары `ключ="значение"`. Те, что имеют значение:

- **`tvg-id`** — идентификатор, связывающий этот канал с передачей в
  телепрограмме XMLTV. Это самая частая причина того, что программа
  загружается, но ничего не показывает: плейлист и программа расходятся в
  идентификаторе, и ничего не совпадает.
- **`tvg-name`** — название канала для сопоставления с программой; оно не
  всегда совпадает с тем, что видно на экране.
- **`tvg-logo`** — адрес логотипа канала. Это картинки, забираемые по сети, по
  одной на канал, — потому большой список в первый раз не сразу выглядит
  законченным.
- **`group-title`** — категория, в которую занесён канал. Каждый заголовок
  категории, мимо которого вы прокручиваете в плеере, был напечатан здесь вашим
  провайдером, канал за каналом. Это же и причина, по которой
  [категории стоит приручить самостоятельно](/ru/blog/порядок-в-большом-плейлисте/).

**Отображаемое название.** После запятой всё до конца строки — это то название,
которое вы действительно видите. Это простой текст без кавычек, поэтому запятая
внутри названия канала — настоящая ловушка формата.

## Адрес

```
http://example.com/live/one.ts
```

Строка сразу после `#EXTINF` — то место, где живёт видео. Это единственная
строка файла, которая при воспроизведении обращается к сети, и именно она
решает, [как поведёт себя поток](/ru/blog/протоколы-hls-dash-rtsp/): адрес с
`.m3u8` — это поток HLS, доставляемый сегментами, адрес с `.ts` — непрерывный
транспортный поток.

Отсюда два полезных вывода. Первый: запись со строкой описания, но без адреса
невидима, потому что играть нечего. Второй: плейлист, который прекрасно
загружается, но ни один канал не открывается, — это плейлист с целыми
названиями и мёртвыми адресами, то есть проблема
[у провайдера, а не в плеере](/ru/blog/что-делает-iptv-плеер/).

## Чего там нет

Не менее поучительно то, что формат вместить не может:

- **Никакого видео.** Плейлист на сорок тысяч каналов — это несколько мегабайт
  текста. Ни один его кадр не является картинкой.
- **Никакого входа в аккаунт.** Там, где нужны учётные данные, они обычно
  вшиты в сами адреса, — потому ссылку на плейлист следует считать паролем.
- **Никакого живого соединения.** Файл — снимок того, что существовало в момент
  получения. Каналов, добавленных позже, в нём нет; это и есть настоящее
  отличие от [API Xtream Codes](/ru/blog/xtream-codes-или-m3u/) и причина того, что
  [важно, где лежит список](/ru/blog/ссылка-на-плейлист-или-файл-на-устройстве/).
- **Никакой заявленной кодировки.** Ничто в формате не сообщает собственную
  кодировку — ровно поэтому
  [названия каналов иногда приходят символами](/ru/blog/имена-каналов-в-виде-символов/).

## Прочитать свой

Если список ведёт себя странно, откройте его и посмотрите. Отсутствующий
`#EXTM3U`, пустой `group-title` в каждой строке, нигде не проставленный
`tvg-id`, название со случайной запятой — у каждого своя отчётливая подпись в
плеере, и каждое видно за десяток секунд чтения.

Формат достаточно мал, чтобы уместиться в голове целиком. Это редкость, и ею
стоит воспользоваться.
